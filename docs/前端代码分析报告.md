# Kmap 前端代码分析报告

## 1. 当前整体架构说明

### 1.1 技术栈

- **框架**：React 19 + TypeScript
- **构建工具**：Vite 6.2
- **样式方案**：Tailwind CSS 4.1 + clsx + tailwind-merge
- **UI 组件**：Lucide React 图标库
- **动效**：Motion
- **数据可视化**：D3.js（已引入，图谱增强待后续使用）
- **产品方向**：Android 本地应用的界面层

### 1.2 当前架构模式

项目已从“单文件组件化架构”进入“首轮模块化架构”：

- `src/App.tsx` 仅负责应用壳层、页面切换和底部导航装配
- 5 个一级页面已经拆分到 `src/pages/`
- 底部导航抽离到 `src/components/navigation/BottomNav.tsx`
- 类型、工具、服务、平台适配占位层已独立成目录
- 当前页面切换仍由 `currentTab` 驱动，尚未迁移到 React Router

- 已具备迁移到 React Router 的结构基础

## 2. 核心模块分析

### 2.1 应用壳层 (`App.tsx`)

- **职责**：应用入口、页面切换、过场动画、底部导航挂载
- **现状**：职责明显收敛，已不再承载具体业务页面实现
- **后续方向**：迁移到路由驱动，进一步减少条件渲染逻辑

### 2.2 底部导航组件 (`BottomNav`)

- **位置**：`src/components/navigation/BottomNav.tsx`
- **功能**：全局页面导航，支持 5 个核心模块切换
- **特点**：
  - 对话按钮使用凸起样式突出主入口
  - 激活态高亮
  - 适合移动端底部固定布局

### 2.3 首页 (`DashboardPage`)

- **位置**：`src/pages/DashboardPage.tsx`
- **功能**：展示知识网络概览
- **模块**：
  - 头部信息区
  - 统计卡片
  - 图谱预览
  - 最近活动列表
- **数据来源**：`src/data/mockActivities.ts` + 页面内硬编码统计数据

### 2.4 文档页 (`DocumentsPage`)

- **位置**：`src/pages/DocumentsPage.tsx`
- **功能**：文档上传、状态轮询、筛选、删除
- **现状**：已对接后端接口，是当前页面中业务逻辑最重的一页
- **已具备能力**：
  - 文件上传
  - 上传进度显示
  - 文档状态轮询
  - 搜索与筛选
  - 删除文档
- **后续方向**：继续拆成筛选栏、列表项、上传区、轮询 hook

### 2.5 图谱页 (`GraphPage`)

- **位置**：`src/pages/GraphPage.tsx`
- **功能**：展示知识图谱静态预览和节点详情面板
- **现状**：仍为静态演示页面，尚未对接真实图谱数据和交互

### 2.6 对话页 (`ChatPage`)

- **位置**：`src/pages/ChatPage.tsx`
- **功能**：展示对话 UI 原型
- **现状**：已具备基础聊天布局，但尚未对接真实对话接口

### 2.7 设置页 (`SettingsPage`)

- **位置**：`src/pages/SettingsPage.tsx`
- **功能**：管理 LLM 服务商与 Embedding 配置
- **现状**：
  - 已对接服务商相关接口
  - 支持新增、编辑、删除、测试连接
  - 仍是一个较大的页面文件，适合继续拆分

## 4. 当前问题清单

### 4.1 架构层问题

- 仍未接入 React Router
- 页面切换仍依赖 `currentTab`
- `DocumentsPage` 和 `SettingsPage` 文件体积仍偏大
- 状态管理仍以内置 hooks 为主，未建立统一 store

### 4.2 App 化问题

- Android 宿主工程尚未初始化
- 文件、权限、分享等原生能力尚未落地
- 浏览器调试与 App 宿主行为之间仍有差异

### 4.3 功能层问题

- 图谱页仍为静态展示
- 对话页尚未对接真实对话服务
- 首页统计数据尚未对接真实接口

## 5. 重构收益评估

当前首轮拆分已经带来以下收益：

- `App.tsx` 明显瘦身，根组件职责清晰
- 一级页面已具备独立演进能力
- 为引入路由和平台桥接创造了条件
- 公共类型、工具和服务不再混在单文件中

## 6. 后续建议

### 6.1 高优先级

- 引入 React Router
- 继续拆分 `DocumentsPage` 与 `SettingsPage`
- 细化 `platform/` 接口并准备接入 Capacitor
- 建立 `stores/` 或基于 hooks 的状态分层

### 6.2 中优先级

- 把 `api.ts` 按领域拆成多个 service 文件
- 把文档轮询逻辑抽成 hook
- 为图谱和对话定义独立领域类型

### 6.3 低优先级

- 增加单元测试
- 优化图谱性能
- 清理临时展示数据
