# Kmap 前端代码分析报告

## 1. 整体架构说明

### 1.1 技术栈
- **框架**: React 19 + TypeScript
- **构建工具**: Vite 6.2
- **样式方案**: Tailwind CSS 4.1 + clsx + tailwind-merge
- **UI 组件**: Lucide React 图标库
- **动效**: Motion (Framer Motion)
- **数据可视化**: D3.js (已引入但暂未使用)
- **后端依赖**: Express + better-sqlite3 (全栈项目结构)

### 1.2 架构模式
当前采用**单文件组件化架构**，所有功能模块均在 `App.tsx` 中实现：
- 单一入口文件 `App.tsx` 包含所有页面组件和业务逻辑
- 底部导航栏作为全局组件，控制页面切换
- 采用状态驱动的页面渲染方式，通过 `currentTab` 状态变量控制不同视图的显示与隐藏
- 使用 React Hooks 管理组件状态和生命周期

### 1.3 目录结构
```
src/
├── App.tsx          # 主应用文件，包含所有组件和业务逻辑
├── main.tsx         # 应用入口文件
└── index.css        # 全局样式文件
```

### 1.4 页面路由
采用**客户端路由**，通过状态变量实现页面切换，共包含5个一级页面：
- `home` - 首页/仪表盘
- `docs` - 文档管理页
- `graph` - 知识图谱页
- `chat` - 对话交互页
- `settings` - 系统设置页

## 2. 核心功能模块分析

### 2.1 底部导航组件 (BottomNav)
- **功能**: 全局页面导航，支持5个核心功能模块切换
- **特点**:
  - 对话功能按钮采用特殊样式，突出核心功能
  - 支持激活状态高亮显示
  - 移动端友好的固定底部设计
- **依赖**: Tab 类型定义、图标组件

### 2.2 首页/仪表盘 (Dashboard)
- **功能**: 提供知识网络概览
- **核心模块**:
  - 头部信息区：应用标识和搜索入口
  - 统计卡片：文档总数、知识节点、关联关系、查询次数四个核心指标
  - 知识图谱可视化预览：展示核心概念和关联关系
  - 最近活动列表：展示文件处理和关联建立的动态
- **数据来源**: MOCK_ACTIVITIES 模拟数据

### 2.3 文档管理页 (DocumentsView)
- **功能**: 知识库文件管理
- **核心模块**:
  - 搜索栏：支持文件搜索
  - 筛选标签：全部、已索引、正在拆分、错误四种状态筛选
  - 文档列表：展示文档名称、大小、时间、处理状态等信息
  - 状态标识：不同文件类型和处理状态使用不同颜色标识
- **数据来源**: MOCK_DOCS 模拟数据

### 2.4 知识图谱页 (GraphView)
- **功能**: 知识网络可视化探索
- **核心模块**:
  - SVG 图谱展示：节点和关系的可视化呈现
  - 视图切换：支持3D探索和列表视图切换
  - 节点详情面板：点击节点显示实体详情、关联统计、操作按钮
  - 动效支持：面板滑入/滑出动画
- **当前状态**: 静态展示，尚未实现交互式图谱操作

### 2.5 对话交互页 (ChatView)
- **功能**: 与知识图谱进行自然语言交互
- **核心模块**:
  - 对话历史展示：用户提问和AI回答的聊天界面
  - 消息输入框：支持文本输入和附件上传
  - 回答操作：复制、点赞、重新生成等功能
- **当前状态**: 静态模拟对话，尚未实现真实的LLM交互

### 2.6 系统设置页 (SettingsView)
- **功能**: 系统参数配置
- **核心模块**:
  - LLM 配置：服务商选择、模型选择、API密钥设置、温度参数调整
  - 向量模型配置：Embedding模型和向量维度设置
  - 配置提示：显示当前配置状态和注意事项
- **当前状态**: 静态表单，尚未实现配置持久化

## 4. 需要对接的后端API接口需求清单

### 4.1 统计数据接口
```
GET /api/statistics
```
- **功能**: 获取首页统计数据
- **返回字段**:
  - docCount: 文档总数
  - nodeCount: 知识节点数
  - relationCount: 关联关系数
  - queryCount: 查询次数
  - docCountChange: 文档总数变化率
  - nodeCountChange: 知识节点变化率
  - relationCountChange: 关联关系变化率
  - queryCountChange: 查询次数变化率

### 4.2 活动日志接口
```
GET /api/activities
```
- **功能**: 获取最近活动列表
- **参数**: limit(可选，默认10)
- **返回字段**: 与 Activity 接口一致

### 4.3 文档管理接口

#### 4.3.1 获取文档列表
```
GET /api/documents
```
- **参数**:
  - status: 筛选状态 (all/indexed/splitting/error)
  - search: 搜索关键词
  - page: 页码
  - pageSize: 每页数量
- **返回字段**: 文档列表、总数量、分页信息

#### 4.3.2 文档上传
```
POST /api/documents/upload
```
- **参数**: FormData 文件对象
- **返回**: 上传结果、文档ID、处理状态

#### 4.3.3 文档详情
```
GET /api/documents/:id
```
- **返回**: 文档详细信息、解析内容、相关节点

#### 4.3.4 删除文档
```
DELETE /api/documents/:id
```
- **返回**: 删除结果

### 4.4 知识图谱接口

#### 4.4.1 获取图谱数据
```
GET /api/graph
```
- **参数**:
  - centerNodeId: 中心节点ID(可选)
  - depth: 展开深度(默认2)
  - limit: 节点数量限制
- **返回**:
  - nodes: 节点列表 (id, label, type, size, position)
  - edges: 关系列表 (id, source, target, relation, weight)

#### 4.4.2 节点详情
```
GET /api/graph/nodes/:id
```
- **返回**: 节点详细信息、关联节点统计、引用文献、重要度等

#### 4.4.3 搜索节点
```
GET /api/graph/search
```
- **参数**: keyword: 搜索关键词
- **返回**: 匹配的节点列表

### 4.5 对话接口

#### 4.5.1 发送消息
```
POST /api/chat/message
```
- **参数**:
  - message: 用户提问内容
  - context: 上下文消息ID列表(可选)
  - nodeId: 关联的知识节点ID(可选)
- **返回**: AI回答内容、引用来源、相关节点推荐

#### 4.5.2 对话历史
```
GET /api/chat/history
```
- **参数**: page, pageSize
- **返回**: 对话历史列表

#### 4.5.3 重新生成回答
```
POST /api/chat/regenerate
```
- **参数**: messageId: 要重新生成的消息ID
- **返回**: 新的回答内容

### 4.6 系统配置接口

#### 4.6.1 获取配置
```
GET /api/settings
```
- **返回**: 当前系统配置(LLM、向量模型等)

#### 4.6.2 保存配置
```
PUT /api/settings
```
- **参数**: 配置项对象
- **返回**: 保存结果

## 5. 技术债务和优化建议

### 5.1 架构优化建议

#### 5.1.1 代码结构重构
- **问题**: 所有代码集中在单个 App.tsx 文件中(600+行)，不利于维护和扩展
- **建议**:
  - 按模块拆分文件：components/、pages/、types/、hooks/、services/ 等目录
  - 每个页面组件独立成文件
  - 公共组件(导航、按钮、卡片等)抽离为独立组件
  - 类型定义统一管理

#### 5.1.2 状态管理
- **问题**: 目前仅使用 useState 管理简单状态，随着功能扩展会出现状态共享问题
- **建议**:
  - 引入轻量级状态管理方案(如 Zustand、Jotai)或使用 React Context
  - 实现全局状态管理，包括用户信息、配置信息、全局通知等

#### 5.1.3 路由方案
- **问题**: 目前通过状态变量控制页面切换，不支持浏览器前进后退、URL路由、页面书签等功能
- **建议**:
  - 引入 React Router 实现客户端路由
  - 每个页面对应独立URL路径
  - 支持路由参数传递(如图谱节点ID、文档ID等)

### 5.2 功能完善建议

#### 5.2.1 知识图谱交互
- **问题**: 当前图谱为静态SVG，无交互能力
- **建议**:
  - 使用 D3.js 或专门的图谱库(如 react-force-graph)实现交互式图谱
  - 支持节点拖拽、缩放、点击展开、关系高亮等操作
  - 实现3D视图模式

#### 5.2.2 文档处理流程
- **问题**: 文档状态只有静态展示，无实际处理流程
- **建议**:
  - 实现文档上传功能
  - 接入后端文档解析、拆分、索引的异步处理流程
  - 实时显示处理进度和状态更新

#### 5.2.3 对话功能增强
- **问题**: 当前为静态对话展示
- **建议**:
  - 实现真实的LLM对接
  - 支持流式响应输出
  - 实现引用来源展示、相关节点关联
  - 支持多轮对话上下文管理

### 5.3 性能优化建议

#### 5.3.1 虚拟滚动
- **问题**: 文档列表、对话历史等长列表在数据量大时会有性能问题
- **建议**:
  - 引入虚拟滚动组件(如 react-window)处理大量数据
  - 实现列表分页加载和无限滚动

#### 5.3.2 图谱性能
- **问题**: 知识图谱节点数量大时渲染性能会下降
- **建议**:
  - 实现节点按需加载
  - 支持大图的层级展示和聚合功能
  - 使用 WebGL 渲染提高性能

### 5.4 代码质量建议

#### 5.4.1 类型系统完善
- **问题**: 现有类型定义较为简单，缺少API接口类型、组件Props类型等
- **建议**:
  - 完善所有组件的Props类型定义
  - 定义API请求和响应的完整类型
  - 启用严格的TypeScript检查规则

#### 5.4.2 API层封装
- **问题**: 暂无API调用层，未来对接后端时会导致代码混乱
- **建议**:
  - 统一封装API请求层
  - 实现请求拦截、响应处理、错误统一处理
  - 加入请求缓存和重试机制

#### 5.4.3 错误处理
- **问题**: 暂无全局错误处理机制
- **建议**:
  - 实现React错误边界捕获组件错误
  - 统一处理API请求错误
  - 加入用户友好的错误提示和反馈机制

#### 5.4.4 可访问性
- **问题**: 目前较少考虑无障碍访问
- **建议**:
  - 补充必要的ARIA属性
  - 支持键盘导航
  - 确保颜色对比度符合标准

### 5.5 工程化建议

#### 5.5.1 代码规范
- **问题**: 暂无统一的代码规范配置
- **建议**:
  - 接入ESLint和Prettier
  - 配置代码提交前检查钩子
  - 统一代码风格

#### 5.5.2 单元测试
- **问题**: 暂无测试代码
- **建议**:
  - 接入Vitest测试框架
  - 为核心组件和工具函数编写单元测试
  - 逐步提高测试覆盖率

#### 5.5.3 构建优化
- **建议**:
  - 配置代码分割，按路由懒加载
  - 优化依赖打包体积
  - 配置CDN资源加速
