# 基于Kmap项目的「纯本地优先+云端可选」完整重构方案

完全贴合项目现有技术栈与目录结构，**90%以上前端代码可直接复用**，无需推翻重写；实现「安装即离线可用，按需切换云端」的核心目标，同时解决原项目的已知缺口与联调痛点。

---

## 一、重构核心原则与架构设计

### 核心目标

1. **100%纯本地运行**：无需任何后端服务、不联网、不联调，所有能力打包进APK，安装即可用

2. **云端能力无缝兼容**：保留原项目完整的云端API调用能力，可一键切换模式，原有后端代码100%复用

3. **最小侵入改造**：不推翻原项目的React+Capacitor+Android技术栈，前端业务代码几乎不用修改

### 重构后核心架构（兼容原项目结构）

原架构：`React前端 → Capacitor壳 → 云端FastAPI后端 → 各类云端服务`

新架构（四层双模式）：

```Plain Text

┌── 前端UI层（src/，90%复用原代码）：页面、组件、路由、状态管理
│    ↓ 统一调用入口
├── 双模式业务网关层（新增）：全局模式切换，自动路由「本地/云端」实现
│    ┌───────────────┬───────────────┐
├── Capacitor原生插件层（新增）  云端兼容层（原backend/，100%保留）
│    ↓ 本地能力封装                ↓ 原后端API完全复用
└── Android本地引擎层（核心重构）：替代所有云端服务，全在APK内运行
     ├── 本地存储引擎（Room/SQLite）→ 替代原PostgreSQL
     ├── 本地向量引擎（sqlite-vss）→ 替代原Qdrant向量数据库
     ├── 本地文档处理引擎 → 替代原Unstructured+RabbitMQ
     ├── 本地AI推理引擎（ONNX Runtime Mobile）→ 替代云端LLM/Embedding服务商
     └── 本地任务调度（Coroutine/WorkManager）→ 替代原异步消息队列
```

## 二、分模块重构方案（完全对应原README的功能模块）

### 1. 应用壳层与导航（原项目已落地）

✅ **100%完全复用，无需修改**

原有的`React Router + HashRouter`、底部导航、页面切换动画，纯前端实现，本地/云端双模式通用。

### 2. 文档管理模块（原项目部分完成）

#### 原云端逻辑

前端上传 → 后端接收 → Unstructured解析 → 分片 → Embedding → 写入PostgreSQL/Qdrant → 返回前端

#### 本地化重构（完全替代云端链路）

1. **文件选择与读取**：完全复用原项目已封装的Capacitor原生文件选择、权限、读取能力，无需修改

2. **本地文档解析**：用Android原生库替代云端Unstructured，无需联网

    - PDF：PdfBox-Android

    - MD/TXT：原生直接读取

    - Office文档：POI-Android

3. **分片与元数据存储**：写入Android Room数据库（谷歌官方SQLite封装），表结构与原后端完全对齐，替代PostgreSQL

4. **向量生成与存储**：调用本地AI引擎生成Embedding，写入sqlite-vss（SQLite向量扩展），替代原Qdrant云端向量库

5. **业务接口对齐**：封装的本地接口，**请求参数、返回格式与原后端** **`/api/v1/documents`** **完全一致**

6. **云端兼容**：切换云端模式时，自动路由到原后端接口，前端代码无感知

### 3. 服务商配置模块（原项目已落地）

#### 本地化重构

1. **UI完全复用**：原有的设置页、服务商增删改查、测试连接能力全部保留

2. **配置存储双适配**：本地模式下存入本地SQLite，云端模式下同步到后端，网关层统一处理

3. **新增「本地模型」服务商类型**：支持配置本地内置/下载的Embedding、LLM模型，设置推理参数、测试本地模型加载与推理

4. **统一适配层**：封装`chat()`、`embedding()`统一接口，底层自动适配「本地模型/云端服务商」，前端与业务逻辑无需关心实现

### 4. 聊天模块（原项目基础可用）

#### 本地化重构

1. **聊天页UI 100%复用**：无需修改页面布局、消息展示、输入框逻辑

2. **双模式消息处理**：

    - 本地模式：调用本地AI引擎的LLM推理，结合本地向量检索实现RAG增强

    - 云端模式：直接复用原后端`/api/v1/chat`接口，无需修改

3. **本地RAG完整链路**：用户提问 → 本地生成Embedding → 本地向量库检索相关文档片段 → 拼接Prompt → 本地LLM生成回答 → 前端展示，全程离线

4. **能力补齐**：本地实现流式响应（Kotlin Flow推送给前端）、会话历史存储（本地SQLite）、引用来源展示，解决原项目的已知缺口

### 5. 知识图谱模块（原项目概览版）

#### 本地化重构

1. **图谱页UI 100%复用**：节点渲染、点击交互、详情展示完全保留

2. **本地图谱生成**：通过本地LLM从文档中提取实体与关系，存入本地SQLite实现的轻量图结构（点边表），替代原云端图谱能力

3. **接口对齐**：本地图谱查询接口与原后端`/api/v1/graph/overview`规范完全一致，网关层自动路由

4. **能力升级**：支持本地实体关系查询、节点展开、图谱过滤，解决原项目仅概览视图的缺口

### 6. 首页仪表盘模块（原项目原型阶段）

1. **UI完全复用**：保留原页面布局与样式

2. **双模式数据适配**：

    - 本地模式：从本地数据库统计文档数量、会话数、模型状态、向量库规模等实时数据，替换原mock数据

    - 云端模式：调用原后端统计接口，无缝切换

### 7. Android宿主与平台桥接模块

1. **100%保留原Capacitor Android工程**：无需推翻重建，应用ID、构建脚本、签名配置完全复用

2. **原生能力扩展**：在原有的平台桥接封装基础上，新增本地模型管理、数据库备份恢复、文件导入导出等Capacitor自定义插件

3. **权限与生命周期适配**：补充文件读写、后台任务、模型推理所需的Android权限，适配后台文档处理、向量生成的生命周期

## 三、核心「双模式切换」实现方案（零侵入前端业务）

这是实现「纯本地+云端可选」的核心，完全不改动前端业务代码，切换无缝。

1. **新增全局模式开关**：在原有的设置页，新增「运行模式」选项：`纯本地模式` / `云端模式`，配置保存到本地存储

2. **新增统一业务网关层** **`src/services/gateway.ts`**：

    - 封装原项目所有后端API接口，规范统一的请求参数与返回格式

    - 前端所有业务页面，必须通过网关层调用能力，禁止直接调用axios或原生API

    - 根据当前选中的模式，自动路由到对应实现：

        - 纯本地模式：调用Capacitor自定义插件的本地能力接口

        - 云端模式：调用原后端的HTTP API，完全复用原有逻辑

3. **核心约束**：本地插件接口与云端API的**入参、出参格式100%对齐**，确保前端业务代码零修改，切换模式无感知

## 五、关键技术选型推荐（贴合原项目栈，避坑优先）

|原云端组件|本地替代方案|核心优势|
|---|---|---|
|FastAPI后端服务|Capacitor自定义插件+Kotlin原生代码|完美适配原项目架构，JS可直接调用，接口规范可与云端100%对齐|
|PostgreSQL关系数据库|Android Room Persistence Library|谷歌官方推荐，稳定兼容SQLite，表结构可与原后端无缝对齐|
|Qdrant向量数据库|sqlite-vss|基于SQLite的轻量向量扩展，与本地存储无缝集成，无需额外服务，极易封装|
|Unstructured文档解析|PdfBox-Android + POI-Android|成熟稳定，支持绝大多数文档格式，纯本地解析，无需联网|
|RabbitMQ异步队列|Kotlin Coroutine + WorkManager|Android原生异步方案，支持后台执行，无需服务端依赖|
|云端LLM/Embedding服务商|ONNX Runtime Mobile + 量化开源模型|兼容性强，支持绝大多数开源模型，量化后体积小，手机端可流畅运行|
